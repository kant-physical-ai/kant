# Linux 노트북 실행 가이드

대상: Ubuntu 24.04 / ROS 2 Lyrical, 2026-10-13.
작업 폴더: `$HOME/waffle-lyrical-slam`.
명령은 Linux 노트북 터미널에서 실행한다. Windows ROS 설치는 필요 없다.
검증 결과는 `VALIDATION.md`를 함께 확인한다.

## 1. 공통 확인

```bash
nvidia-smi
source /opt/ros/lyrical/setup.bash
echo "$ROS_DISTRO"  # lyrical
```

새 터미널마다 환경을 source한다. 한 터미널에서 OpenArm과 Waffle 워크스페이스를
번갈아 겹쳐 source하지 말고 새 터미널을 사용한다. 같은 실습에 참여하는 터미널은
ROS_DOMAIN_ID를 같게 맞춘다. 아래 171/172/174는 각각 독립 검사 번호다.

## 2. Cartographer: 바로 재현 가능한 CPU 검사

```bash
source /opt/ros/lyrical/setup.bash
cd ~/waffle-lyrical-slam
source install/setup.bash
export ROS_DOMAIN_ID=171
python3 synthetic_cartographer_check.py
cat synthetic-result.json
ls -lh maps/synthetic_room.*
```

합성 LiDAR·odometry로 지도 생성과 PGM/YAML 저장을 검사한다.
실제 Waffle이나 Isaac Sim 주행 검사는 아니다. 검사 스크립트는 자신이 시작한
노드를 종료한다. 예상 지도 크기는 132×132셀, 해상도 0.05m다.

## 3. Cartographer: 센서가 발행되는 장면에서 실행

먼저 Isaac Sim 장면에 `/clock`, `/scan`, `/odom`, `/joint_states`와
odom→base_footprint TF를 구성한다. 장면 구성은 `README.md` 3절을 따른다.
현재 제공한 stereo 검사 장면에는 LiDAR·Waffle 차동구동이 없으므로 아래의
Cartographer 실습 장면을 대신하지 않는다.

터미널 A — 로봇 모델:

```bash
source /opt/ros/lyrical/setup.bash
source ~/waffle-lyrical-slam/install/setup.bash
export ROS_DOMAIN_ID=174
ros2 launch waffle_slam_course model.launch.py
```

터미널 B — SLAM:

```bash
source /opt/ros/lyrical/setup.bash
source ~/waffle-lyrical-slam/install/setup.bash
export ROS_DOMAIN_ID=174
cd ~/waffle-lyrical-slam
bash preflight.sh cartographer
ros2 launch waffle_slam_course cartographer.launch.py
```

터미널 C — 화면과 지도 저장(화면 실행과 저장 명령은 각각 별도 터미널):

```bash
source /opt/ros/lyrical/setup.bash
source ~/waffle-lyrical-slam/install/setup.bash
export ROS_DOMAIN_ID=174
rviz2 --ros-args -p use_sim_time:=true
```

RViz Fixed Frame=`map`, Map=`/map`, LaserScan=`/scan`.

```bash
mkdir -p ~/waffle-lyrical-slam/maps
ros2 run nav2_map_server map_saver_cli \
  -f ~/waffle-lyrical-slam/maps/waffle_2d \
  --ros-args -p use_sim_time:=true
ros2 service call /write_state cartographer_ros_msgs/srv/WriteState \
  "{filename: '$HOME/waffle-lyrical-slam/maps/waffle.pbstream', include_unfinished_submaps: true}"
```

각 launch 터미널에서 Ctrl+C로 종료한다. Cartographer와 cuVSLAM을 같은
TF 트리에 동시에 실행하지 않는다.

## 4. Gazebo: TurtleBot3 Waffle + Cartographer

이 노트북에는 빌드가 완료되어 있다. Jazzy 공식 소스의 commit
`45633014a14e8f438495b532a723e4ad45cbbd31`을 Lyrical/Gazebo 10.5에서 빌드했다.
다시 준비할 때는 `bash build_gazebo.sh`를 실행한다. ROS 바이너리는 Lyrical을 사용한다.

기본 월드는 업로드한 `Twin Closed Maze B - A1 R2 Printed Splices.stl`의 미로다.
크기는 약 4.464 × 6.364m, 높이 0.390m이며, 원본의 mm/Y-up을 m/Z-up으로
변환했다. 실행용 사본은 꼭짓점을 1mm 간격으로 정리해 작은 체결부를 단순화했다.
원본 STL은 변경하지 않았다. 시작 위치는 (x=-1.835, y=2.757)m, 진행 방향은 +X다.
충돌 형상은 원본에서 추출한 판넬 40개와 기둥 83개의 박스로 구성한다.
기둥은 60 × 60mm 바닥 외곽을 높이 전체에 적용한 보수적인 근사다.
월드: `src/waffle_slam_course/worlds/twin_closed_maze.sdf`.
메시: `src/waffle_slam_course/models/twin_closed_maze/meshes/maze.stl`.
기존 Gazebo와 SLAM을 종료하고 아래 명령으로 다시 실행해야 새 월드를 읽는다.
기존 월드에서 저장한 PGM/YAML·pbstream은 이 미로용으로 다시 생성한다.

터미널 A — Waffle Gazebo:

```bash
source /opt/ros/lyrical/setup.bash
cd ~/waffle-lyrical-slam
source install/setup.bash
source gazebo_install/setup.bash
export ROS_DOMAIN_ID=174
export GZ_PARTITION=waffle_course
ros2 launch waffle_slam_course gazebo.launch.py gui:=true
```

화면 없이 실행하려면 `gui:=false`로 바꾼다. `gui:=true`는 Linux 데스크톱
터미널에서 사용한다. 이 launch가 robot_state_publisher도 실행하므로
3절의 `model.launch.py`를 추가로 실행하지 않는다.

터미널 B — 3절의 Cartographer 명령으로 실행한다(domain=174).
터미널 C — 상태 확인/이동:

```bash
source /opt/ros/lyrical/setup.bash
source ~/waffle-lyrical-slam/install/setup.bash
export ROS_DOMAIN_ID=174
ros2 topic echo /scan --once
ros2 topic echo /odom --once
ros2 topic type /cmd_vel  # geometry_msgs/msg/TwistStamped
timeout 3 ros2 topic pub --rate 10 /cmd_vel geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.1}, angular: {z: 0.0}}}'
ros2 topic pub --once /cmd_vel geometry_msgs/msg/TwistStamped '{}'
```

3秒 직진 명령 후 **0속도 명령까지 실행**한다. 회전은 linear.x=0.0,
angular.z=0.2로 바꾼다. 이 Gazebo bridge는 TwistStamped이며 Isaac Sim의
Twist 구독 설정과 다르다. 종료 전 0속도를 보내고 SLAM, Gazebo 순서로 Ctrl+C.
지도 저장은 3절의 map_saver_cli와 write_state를 사용한다.

### 키보드 텔레옵

Linux에 `ros-lyrical-teleop-twist-keyboard` 2.4.1을 설치했다.
Gazebo 실행 후 **새 Linux 터미널**에서 실행한다. 다른 /cmd_vel 발행기는 중지한다.

```bash
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=174
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args \
  -p stamped:=true -p frame_id:=base_footprint -p use_sim_time:=true \
  -p speed:=0.1 -p turn:=0.2
```

| 키 | 동작 |
|---|---|
| i / , | 전진 / 후진 |
| j / l | 제자리 좌회전 / 우회전 |
| u / o | 전진하면서 좌회전 / 우회전 |
| k 또는 Space | 정지 |
| q / z | 최대 선속도·각속도 10% 증가 / 감소 |
| Ctrl+C | 0속도 명령 후 종료 |

키보드 입력은 텔레옵 터미널에 포커스가 있어야 받는다. 손을 떼는 동작만으로
자동 정지하지 않으므로 `k`로 정지한 뒤 종료한다. 시작 속도는 0.1m/s,
각속도는 0.2rad/s다. 테스트용 독립 토픽에서 i/j/k 입력의 TwistStamped 값과
Ctrl+C 종료를 확인했다. 실제 GUI에서 키보드로 주행하는 검사는 별도다.

새 환경에서 패키지가 없으면 Linux에서
`sudo apt-get install ros-lyrical-teleop-twist-keyboard`로 설치한다.
Isaac Sim의 구동 장면이 Twist를 구독하면 `stamped:=false`로 실행하고
frame_id 인자는 제거한다. 현재 제공한 cuVSLAM stereo rig는 자동 이동 장면이며
/cmd_vel 구동 컨트롤러가 없으므로 이 키보드 명령으로 이동하지 않는다.

자동 재검사(사용 중인 실습과 다른 domain/partition):

```bash
cd ~/waffle-lyrical-slam
bash check-waffle-gazebo-remote.sh
cat waffle-gazebo-result.json
```

실제 검사에서 직진 0.777m, 반시계 회전 0.966rad, 정지, LiDAR/odom/지도
수신과 PGM/YAML 저장이 통과했다. 이는 작은 경로의 기능 검사이며 위치 정확도나
루프 폐합 성능을 측정한 결과는 아니다. GUI는 별도 검사하지 않았다.

## 5. cuVSLAM: 검증된 GPU 추적·지도 저장 검사

```bash
cd ~/waffle-lyrical-slam
bash run-cuvslam-remote.sh
cat synthetic-cuvslam-result.json
```

이미 준비한 `waffle-cuvslam:5.0-lyrical` Docker 이미지를 사용한다.
합성 stereo 640×480/10Hz로 GPU 추적과 지도 저장을 검사한다.
이전 검사에서 odometry 179개와 `data.mdb` 저장을 확인했다.
새 실행의 결과 수는 타이밍에 따라 달라진다. 10Hz 입력 때문에 기본 30Hz
jitter 기준 경고가 날 수 있다. 이를 실시간 성능 측정으로 해석하지 않는다.

## 6. Isaac Sim 6.1 및 실제 stereo 연동 검사

Isaac Sim은 작업 폴더 안의 `isaacsim-venv`에 설치되어 있다.
기존 시스템 Python과 OpenArm 워크스페이스를 바꾸지 않는다.
제공한 스크립트는 CPU 스레드 4, 단일 GPU로 실행한다. 기본 16스레드의
첫 준비에서 메모리 사용량이 약 14GB까지 증가해 낮춘 설정이다.
Sim venv의 ROS Python 의존성은 empy 3.3.4, lark 1.1.9로 보완했다.

시작 검사:

```bash
cd ~/waffle-lyrical-slam
bash smoke-isaacsim-remote.sh > isaacsim-startup.log 2>&1
tail -n 30 isaacsim-startup.log
cat isaacsim-startup-result.json
```

실제 stereo 렌더링 → cuVSLAM 검사:

```bash
cd ~/waffle-lyrical-slam
bash run-sim-integration-remote.sh
cat sim-cuvslam-result.json
```

실행 상태는 `sim-render.log`, `sim-observation.log`, `sim_cuvslam.log`에 남는다.
이 검사는 작은 방의 이동하는 가상 stereo rig를 사용한다. Waffle 차체의
물리 주행이나 LiDAR 장면은 아니다. 실행 전 `VALIDATION.md`에서 현재 통과
여부를 확인한다. 첫 실행에는 확장 모듈 다운로드와 셰이더 준비가 필요할 수 있다.

실제 검사 결과: stereo 동기화 120쌍, odometry 130개, 위치 x 변화 0.383m,
baseline 0.095m, 중복·역순 영상 stamp 0건. 시작 구간에는 프레임 간격 경고가
있었으며 30Hz 실시간·장시간 안정성을 보장하는 결과는 아니다.

이 조합에서는 기본 CameraInfoHelper의 배열이 잘못 전달된다. 제공한 장면은
`lyrical_camera_info.py`로 실제 USD 보정값을 Lyrical rclpy에서 발행해 해결했다.
이는 CameraInfo 경로의 호환 수정이며 전체 native bridge 포팅은 아니다.

## 7. 직접 만든 Sim 장면에 cuVSLAM 연결

Sim과 아래 컨테이너의 domain을 174, RMW를 rmw_fastrtps_cpp로 맞춘다.
좌우 rectified 영상·CameraInfo와 `/clock`을 발행하고 광학 고정 TF를 준비한다.
토픽·보정값은 `README.md` 3절과 맞춘다. Sim의 odom→base_footprint TF는 끈다.
CameraInfo는 위의 Lyrical 발행 경로를 사용한다. GUI의 기본 CameraInfoHelper를
그대로 사용하지 않는다. 제공 발행기는 평행·무왜곡 pinhole stereo용이다.
자동 검사 observer는 고정 TF를 발행하지만 아래 직접 launch에는 그 기능이 없다.

제공된 가상 rig와 같은 치수일 때는 호스트의 새 터미널 두 개에서 각각
ROS 환경을 source하고 domain=174로 맞춘 뒤 다음 고정 TF를 발행한다.
실제 장착 치수가 다르면 해당 값으로 바꾼다. 자동 검사와 동시에 발행하지 않는다.

```bash
# 왼쪽: 별도 터미널에서 유지
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=174
ros2 run tf2_ros static_transform_publisher \
  --x 0.12 --y 0.0475 --z 0.29 --qx -0.5 --qy 0.5 --qz -0.5 --qw 0.5 \
  --frame-id base_footprint --child-frame-id waffle_left_optical
```

```bash
# 오른쪽: 다른 터미널에서 유지
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=174
ros2 run tf2_ros static_transform_publisher \
  --x 0.12 --y -0.0475 --z 0.29 --qx -0.5 --qy 0.5 --qz -0.5 --qw 0.5 \
  --frame-id base_footprint --child-frame-id waffle_right_optical
```

```bash
cd ~/waffle-lyrical-slam
docker run --rm -it --gpus all --network host --ipc host \
  -e NVIDIA_DRIVER_CAPABILITIES=all -e ROS_DOMAIN_ID=174 \
  -e RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  -v "$PWD:/work" --workdir /work --entrypoint bash \
  waffle-cuvslam:5.0-lyrical
```

컨테이너 안:

```bash
source /opt/ros/lyrical/setup.bash
source /work/install/setup.bash
ros2 launch waffle_slam_course cuvslam.launch.py
```

동일 컨테이너의 별도 셸에서 ROS 환경을 source한 뒤 확인한다.
호스트에는 cuVSLAM 전용 메시지 패키지를 설치하지 않았으므로 status/서비스는
컨테이너 안에서 실행한다:

```bash
ros2 topic echo /visual_slam/status --once
ros2 topic echo /visual_slam/tracking/odometry --once
ros2 run tf2_ros tf2_echo map base_footprint
```

지도 저장 서비스는 컨테이너 안의 별도 셸에서 호출한다. `docker ps`로 현재
컨테이너 ID를 확인하고 `docker exec -it <컨테이너ID> bash`로 들어간다.

```bash
source /opt/ros/lyrical/setup.bash
MAP_DIR=$(mktemp -d /work/cuvslam_map_XXXXXX)
ros2 service call /visual_slam/save_map isaac_ros_visual_slam_interfaces/srv/FilePath \
  "{file_path: '$MAP_DIR'}"
ls -lh "$MAP_DIR"
```

새 빈 폴더를 사용한다. `/work`는 호스트 작업 폴더와 연결되어 저장 파일이 남는다.
지도 재위치 추정 서비스 예시는 `README.md`에 있으며 실제 재위치 추정은 아직
별도 검증하지 않았다. 종료는 launch Ctrl+C 후 컨테이너에서 `exit`.

## 8. 문제 확인 순서

1. GPU 오류: `nvidia-smi`와 컨테이너의 `--gpus all` 확인.
2. 토픽 없음: source, domain, 시뮬레이터 Play, `/clock` 확인.
3. 추적 실패: 좌우 영상 stamp, CameraInfo K/P, baseline 0.095m, optical TF 확인.
4. TF 충돌: Cartographer와 cuVSLAM 중 하나만 실행하고 odom TF 소유자 확인.
5. Isaac Sim 시작 실패: `isaacsim-startup.log`의 첫 dependency/GPU 오류 확인.

현재 노트북은 RTX 3050 Laptop 4GB, RAM 약 16GB다. Isaac Sim 공식 최소
RAM/VRAM보다 낮으므로 작은 장면 통과와 전체 수업 장면의 안정성을 구분한다.
